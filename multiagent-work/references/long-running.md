# 长期中台规则

只在用户明确要求 `长期中台`、跨会话执行、创建独立 Codex 任务、持续推进、无人值守或定时检查时读取本文件。加载 skill 本身不授权这些操作。

## 启动门禁

启动前核对：

- 目标项目及宿主工具返回的真实 `projectId`；路径或同名目录不能代替项目归属；
- 可验收成果、依赖关系、允许修改范围和集成负责人；
- 时间/GPU/费用/并发上限，以及失败、资源冲突和截止时间的停止条件；
- 用户是否明确授权创建独立任务、跨任务派发和需要的定时推进。

缺少会阻止执行的授权或选择时，先完成所有安全的只读准备，再集中询问一次。不要把未知预算当作无限预算。

## 中台与执行任务

- 默认只有一个中台负责分发、状态和心跳。中台、执行与复核任务属于同一已核实项目。
- 每个可独立验收成果对应一个执行任务；同一成果的连续调试留在原任务。需要干净视角的关键复核才新建任务。
- 派发消息包含目标、相关事实、证据路径、输入版本、范围、资源、产物、验收和停止条件，不要求执行任务加载整个中台上下文。
- 执行任务不获得创建更多任务、修改调度、合并、推送或扩大资源的默认权限。
- 并行修改明确文件所有权；worktree 不隔离 GPU、端口、数据库、共享数据或输出目录，这些资源必须另行分配。

## 状态与恢复

优先使用宿主已有状态或目标项目约定的状态入口。创建项目前先检查目标项目的指令、目录规范与允许写入范围；只有项目允许且没有合适入口时才使用 `work/multi-session-workflow.md`。客户/生产仓库或写入范围不明时，不自行创建状态文件，改用宿主状态或请求用户指定位置。只维护一份权威入口，记录当前事实和证据指针，不复制完整对话或为每次心跳创建报告。

最小状态包括：工作包、真实任务标题与 ID、依赖、输入版本、状态、产物、验证、阻塞、下一步和用户验收。状态只能依据工具返回、作业状态和实际产物更新。

统一使用：`PENDING -> RUNNING -> SUCCEEDED | FAILED | BLOCKED | CANCELLED`。`PAUSED` 是调度状态，不自动改变外部作业状态；记录该作业是继续运行并由谁观察，还是已按单独授权取消。恢复时从唯一权威状态入口和宿主工具重新核对，不凭旧对话直接推进。

`中台状态` 只核对和报告，不派发新工作。`中台继续` 在原范围与预算内推进依赖已满足的工作。`中台暂停` 停止新派发和新高成本动作；暂停调度不等于取消已运行作业。`中台验收` 区分自动核验和用户验收。

## 等待、失败与心跳

- 短期等待使用宿主等待工具，不忙轮询，也不靠连续发送“继续”维持运行。
- 长作业记录主机、作业 ID、命令、日志和输出位置。静默、聊天空闲或一次超时不能单独证明失败；先重连和核对，不能重复启动。
- 重试必须有新证据或具体修正。同一失败修正后仍复现且没有新证据时标记受阻；不依赖它的工作可以继续。
- 只有用户明确要求定时检查或无人值守续行才创建 heartbeat。使用同一中台的单一 heartbeat，保存真实 automation ID，不创建重复调度。
- 每次唤醒先核对绝对截止时间、剩余预算和停止余量。已完成、只剩用户复核、达到预算边界或剩余时间不足时，先暂停心跳，再做必要的只读核对。
- 无变化时保持安静；完成、失败、需要用户决策或达到边界时通知。

## 验收与停止

每个执行任务交付目标、实际完成内容、产物、验证命令与结果、未完成项和偏差。主会话验证关键结果；执行任务结束不等于工作包完成。

所有工作包及必要集成自动核验通过后，停止自主推进并交付索引。未经要求不归档任务、不清理 worktree、不删除实验产物，也不自动开始下一研究阶段。
