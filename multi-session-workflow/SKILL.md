# 多会话持续执行

让每个可验收成果对应一个独立任务，在用户离开期间按约定推进，回来后能查清每个任务的工作、产物和验证依据。

## 适用方式与权限

- 先判断用户在设计、启动、恢复还是验收工作流。设计时只完善规则；只有请求实际执行时才建立运行状态。
- 本技能管理应用侧可独立查看的任务。不要以当前任务中的临时子代理替代用户要求的独立执行任务。
- 技能提供操作规则，持续执行依赖宿主的任务工具、调度器和可用运行环境。先发现并读取当前工具说明，不能假定另一台主机或 CLI 有相同能力。
- 启动前确认既有请求是否已明确授权创建独立任务、跨任务派发及定时推进。已有授权沿用；缺少必要授权时，先准备具体工作包，再一次性询问缺失部分。加载技能本身不增加权限。
- 延续用户的原目标、验收标准、资源预算及操作边界。普通实现选择与必要诊断可自主处理；扩大范围、降低指标或增加未经授权的支出不属于自主调度。

## 开始或恢复

1. 找到用户指定的项目、既有计划、运行记录和中台任务。用宿主工具核实中台所属的 `projectId`，将其作为整个工作流唯一的项目标识；项目路径或同名文件夹不能代替应用中的项目归属。当前任务未归属目标项目时，先确定已登记的目标项目并在其中建立中台；缺少项目或必要能力则说明缺口，不降级创建项目外任务。恢复时核对已有任务、调度和作业，不重新创建一整套工作流。
2. 明确完成标准、依赖关系、可修改范围、资源上限和失败后的停止条件。仅补问会阻止实际执行的信息。资源上限未知不等于无限预算。
3. 按可单独验收的成果拆工作包，名称描述具体成果，例如“核对数据划分”“跑通单批次训练”。同一工作包连续调试留在原任务；独立成果或确需无先入结论的复核才开新任务。
4. 在项目已有状态入口维护一份简短记录；没有合适入口时使用项目的 `work/multi-session-workflow.md`。它是恢复和验收所需的运行记录，不写进技能目录，不为每轮检查另建文档。
5. 启动、派发或恢复前读取 [交接与恢复约定](references/coordination.md)。记录里只保存当前事实、必要决策及证据指针，不复制完整会话。
6. 在结束当前中台轮次前，确认后续唤醒已经保存且目标正确；若调度不可用，明确报告不能保证无人值守续行，保留已启动工作的恢复信息。

## 中台和执行任务

- 默认只有一个中台派发任务、更新运行记录和修改心跳。替换中台前确认旧中台不会继续派发；中台 ID 不可凭空推断。
- 中台、执行和复核任务必须属于同一 `projectId`。创建时显式使用项目目标，按宿主规则选择 worktree 或本地工作区；不同 worktree 路径不代表不同项目。创建后及恢复派发前，用工具返回的项目归属核验；不匹配或未知时停止向该任务继续派发，先解决归属问题。后续消息也沿用已核实的任务 ID，不能误用项目外的同名任务。
- 执行任务只完成自身工作包。派发消息应包含自足的执行约定，不要求执行任务加载整个中台技能，也不赋予其继续创建任务或修改调度的默认权限。
- 新任务只接收相关事实、证据位置、约束和待验证假设。需要干净上下文时不完整复制或 fork 旧调试历史。保留已排除原因及依据，避免重复排查。
- 中台常规只读取紧凑状态和交付说明，遇到失败、冲突或验收疑点再读取有关对话、代码或日志。可以保留多个竞争解释，不能把执行任务的猜测升级成事实。

## 执行循环

每轮先执行下文的心跳停止检查，再恢复事实；任何状态写入都以工具结果或实际证据为依据。

1. **核对**：读取最新用户约束、工作包约定、执行任务状态及有关外部作业。未知状态保留为未知。
2. **验核**：检查新提交的产物与该工作包的验收标准；匹配任务 ID、本次尝试、约定版本和输入版本。回答结束不等于作业结束，执行者自报成功不等于验证通过。
3. **更新**：分别维护执行状态、自动核验和用户验收。自动核验通过可解除下游依赖；用户验收仍保持待验收，避免无人值守流程等待用户逐项签字。用户指定的人工关卡除外。
4. **派发**：仅推进依赖已满足且资源允许的工作包。先核对是否已有同一尝试，防止重复派发。相互依赖或写入冲突的工作顺序执行；并发数受用户预算和宿主能力共同限制。
5. **诊断**：失败后做能区分原因的最小检查。重试要说明新证据或修正；同一失败修正后仍复现且没有新证据时，将该工作包记为受阻。其他不依赖它的工作可继续。
6. **等待或结束**：短期等待使用任务等待工具；需要稍后返回时依赖已保存的心跳。不要靠连续发送“继续”或忙轮询维持运行。

## 代码、作业与证据

- 为并行修改明确文件所有权，必要时使用独立 worktree。worktree 不隔离 GPU、数据库、端口、共享数据或输出目录，这些资源另行指定。
- 每个修改工作包明确起始代码状态及集成负责人。下游必须能访问已核验的确切产物；分支上的通过结果不自动代表集成后的版本通过。
- 代码集成遵守已有授权。未获合并授权时保留可审查的修改，并仅阻塞依赖集成的工作；不要让中台和执行任务同时改同一范围。
- 长时间训练等作业使用环境已有的可靠后台机制，记录主机、作业 ID、命令、日志和输出位置。先保存可定位作业的信息，再结束当前执行轮次。
- 用作业状态、退出状态、进度和产物检查判断运行情况；静默、聊天空闲或一次超时都不能单独证明作业失败。失联时先重新连接与核对，不能直接复制启动。
- 结果绑定确切代码状态、配置和有关数据/checkpoint；必要时保留未提交 diff 与有效配置。用户改变标准后，仅重新核验受影响的工作及下游结果，不删除历史证据。

## 心跳

- 每次唤醒先读取当前时间和提示词中的停止边界。已完成、只剩最终复核、已到预算边界或剩余时间不足以完成下一动作并暂停时，立即暂停同一心跳，停止新派发，再读取详细状态、等待任务或做只读复核。不能把暂停放在耗时收尾之后；复核发现问题时也只能在原范围和剩余预算内恢复推进。
- 每次派发和阻塞等待前再次检查剩余预算，并为暂停操作留出余量；截止时间不因重试、恢复或更新心跳而顺延。心跳周期是检查频率，不是保证送达或完成的时限；需要硬截止的作业必须使用运行环境已有的作业超时或预算限制，不能仅依赖提示词。
- 对持续中台使用附着于该中台的 heartbeat。除非用户要求独立周期任务，不为每次检查创建新的中台。
- 通过当前自动化工具创建或更新，沿用已有 automation ID；更新时保留无关字段。工具返回成功并核对保存结果后，才能宣称调度已生效。
- 提示词开头保留中台与项目标识、当前阶段、绝对截止时间（含时区）、停止余量及暂停同一心跳所需信息，随后提供技能和运行记录的位置；可采用 [心跳模板](references/coordination.md#心跳模板)。阶段变化时同步更新同一心跳的阶段，避免最后一次唤醒仍执行过期的派发指令。提示词与最新用户约束冲突时按最新约束处理，不借此延长预算。
- 调整检查频率可以适应作业周期和失败情况，但不能改写原目标、放宽验收或扩大预算。没有可行动变化时保持安静；重要进展、完成、失败或需要用户决策时通知。另行遵守用户要求的周期汇报。
- 中台在活动状态时也可等待执行结果；每次被唤醒仍先核对，不能假设此次触发是唯一触发。
- 无可继续的工作且需要用户决策、预算已达边界或整体自动核验完成时，暂停心跳并说明原因。若仍有已授权作业运行，按既定预算保留必要监测；暂停调度不代表作业已取消。
- 没有实际验证过的后台恢复、重启或调度行为，不宣称有可靠保证；宿主退出、失联或额度不足时报告实际限制。

## 验收与停止

- 每个执行任务提交：目标、实际完成内容、产物位置、验证命令与结果、未完成项和偏差。重要否定结果也可构成完成，前提是符合原工作包的完成标准。
- 中台汇总一张索引：工作包、工具返回的任务标题与 ID、成果、证据位置、自动核验、用户验收、剩余问题。只使用真实返回或已验证的任务入口，不构造未经支持的链接。
- 常规验证在中台完成；只有关键结论、可疑结果或高影响修改确需独立复核时才增加复核任务，且遵循创建任务的授权边界。
- 所有要求的工作和必要集成均自动核验通过后，停止自主推进并交付验收索引；用户验收只能由用户的反馈更新。
- 未经要求不自动归档执行任务、清理 worktree 或删除实验产物，确保用户仍能检查证据。停止后不追加清理、扩展或新的研究任务。
