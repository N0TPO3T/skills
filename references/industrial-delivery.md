# 工业交付与生产变更规则

只在任务涉及客户材料、敏感数据、staging/production、数据库迁移、云资源、线上服务、外部发布、权限/密钥或第三方系统时读取本文件。研究原型和普通本地代码修改不加载本文件。

## 先确定环境与影响面

明确 dev、test、staging、production 或客户环境，涉及的用户/服务/数据、可接受停机、责任人和回退窗口。环境不明且可能产生线上影响时只做只读检查和可审查准备，不执行变更。

有副作用的任务建立最小执行契约：

```text
环境与影响面 | 允许写入 | 禁止动作 | 数据与秘密 | 资源上限 | 验收 | 回滚 | 需再次确认的动作
```

只补齐会改变权限、成本、隐私、合规、线上风险或结果的缺失字段；不为低风险本地修改制造审批流程。

## 独立授权

以下动作不能仅由“中台执行”推断授权：生产写入、数据删除、不可逆 migration、外部发布、客户/第三方通信、权限授予、密钥轮换、付费资源扩容以及向第三方模型披露非公开材料。

执行前解析精确目标，给出影响面和可回滚方案，并等待明确授权。凭证只通过既定秘密管理机制使用，不写入 prompt、日志、仓库或交付物。

## 最小生产变更门禁

1. **Preflight**：核对目标环境、版本、依赖、权限、容量和当前健康状态。
2. **数据与兼容性**：确认备份/恢复可用，schema、API、模型或配置变更对上下游兼容；破坏性 migration 先设计分阶段迁移。
3. **Rollback**：在执行前定义 rollback trigger、恢复步骤、数据兼容性、负责人和可验证的恢复检查。仅有“可以回滚”的表述不算通过。
4. **执行与隔离**：最小变更、最小权限；并行任务隔离 Git 分支/worktree、数据库、队列、对象存储前缀、云配额和 deployment target。
5. **Post-change check**：检查服务健康、关键路径、监控/SLO、错误率和数据完整性；失败达到 trigger 时停止并回滚或请求用户决策。

任一必要门禁缺失时，只完成安全的准备或 staging 验证，不把“功能已实现”写成“可以上线”。

## 交付证据

交付时记录实际变更、环境、版本、验证、监控结果、未完成项和回滚状态。若涉及许可证、供应链、隐私或合规要求，只报告有一手证据支持的检查结果；未知项保持未知并交给对应责任人决策。

不自动进行发布后的长期监控。用户明确要求持续观察时，转入长期中台规则并设定截止时间与通知条件。
