# BOSS直聘（Windows 桌面客户端）自动筛选+打招呼 —— 实操经验纪要

> 来源：2026-09-09 实跑（核对推荐流 30+ 人，成功打招呼 10 人）。
> 环境：Windows 11 / 100% DPI / BOSS直聘桌面客户端（Electron）窗口 1077x816，招聘者账号。
> 配套工具：`C:\Users\EDY\Code\HR\tools\`（wrect/shot/click/keys/scroll/zoom/invert/snap.ps1）。

## 0. 铁律
1. **视觉模型读"控件像素坐标"极不可靠**：实测同一目标多次读数漂移 ±30~600px。任何"读坐标→直接点"都不可信。
2. 可靠闭环：局部放大 3-4x 定位（误差降到 ±15px 内）→ 光标移到候选点 → 若有人在屏可让其目视确认 → 点击 → 截图验证效果（弹窗出现/页面变化/按钮文字）。
3. 视觉"文字读取"弱：白字在青绿按钮上读不出 → 用 `invert.ps1`（反相）后再读，或靠位置语义判断。
4. 每步操作前重查窗口 rect（窗口可能被移动/缩放/重启），坐标全部窗口相对，换算：全局 = 窗口 origin + 相对坐标（本机 100% DPI 无缩放）。
5. 用户在场时"点名字/按钮"前先问一句是否对准，比点错返工快得多；用户发消息会移动鼠标，点击前必须重新定位。

## 1. 本机实测固定锚点（1077x816 布局，布局变化需重测）
- 详情页右侧操作栏（从上到下）：
  - 图标行：收藏 / 转发 / 举报 / 不合适
  - **青绿实心按钮 = 「打招呼」** ≈ (945,150) ← 招呼点这里
  - 白底描边按钮 = 「帮我联系」（付费顾问服务）≈ (945,215) ← **不要点**，点了弹「意向沟通极速版」付费窗且不会打招呼
- 「已向牛人发送招呼」弹窗 → 「知道了」≈ (762,494)（弹窗居中，位置基本固定）
- 详情页右上角 X（关闭已沟通详情，Esc 对此态无效）≈ (1060,45)
- 侧栏（y 为实测近似）：牛人推荐列表入口 (46,255)；牛人搜索 (46,300)；职位 (46,330~345)；收藏牛人 ~(46,390)；数据 ~(46,470)。**侧栏图标无文字，视觉读图标不可靠，以上按功能实测记住**。
- 已打招呼详情特征：右侧变聊天面板（有"送达"）；此时 Esc 无效，用右上 X。

## 2. 流程模板（每个候选人）
1. 列表卡片预筛：姓名/年龄/院校标签（211/985/双一流 显示在卡上）/期望城市/公司/薪资。城市不符（非杭州）、职能不符（算法/仿真/售前/CFD/教学）、薪资远超岗位（期望下限 > 岗位上限很多）→ 不开详情，直接记录跳过。
2. 预筛通过 → 点**姓名文字**进详情（点卡片中部偶发无效；无效就滚动 1 格重新定位再点；列表位置每次返回都会漂移 ±20-80px）。
3. 详情核对：读教育（学校/专业/全日制推断：时间线连续 4 年）+ 核心经历。注意：**详情页没有教育栏 ≠ 没教育**（看列表卡右侧时间线，例：杨正清详情无教育栏但列表卡显示南昌大学 211 → 修正判定）。
4. 判定通过 → 点 (945,150) 打招呼 → 2 秒后应出现「已向牛人发送招呼」弹窗（**成功标志**；若出现「意向沟通极速版」= 点的白钮或推销弹窗，招呼也可能已发出，需看聊天面板确认）→ 点「知道了」(762,494)。
5. 点 X (1060,45) 回列表 → 滚动下一人。滚动时鼠标放列表区 (600,500)。

## 3. 坑与对策
- **付费/推销弹窗**（意向沟通极速版 30次/468直豆 等）：招呼本身免费，弹窗只是增值推销；绝不购买。关闭：Esc 有时无效；点遮罩会**穿透点击到下层控件**（曾因此切走页面）；安全关闭=点弹窗外的顶部遮罩条（实测 (600,45) 有效）。
- **客户端可能自行重启**（进程 pid 变）：回到默认页面，筛选条件可能丢 → 让用户重设/确认列表再跑。
- **筛选条件位置**：条件在牛人推荐流右上角条件框（如"机械工程师（机器人方向）_杭州 15-25K"），点右侧箭头展开筛选面板；面板可能比窗口高，需在面板内滚动才能看到底部（学历/薪资/确定）。用户若已自设筛选，别动面板。
- **推荐列表无尽头**：是算法流，会循环/重复出现已招呼的人；靠姓名清单人工跳过。已招呼的人仍显示普通卡片（无标记）。
- **查看简历有每日额度**（"今日还可查看 N 人"）：先卡片预筛再开详情，别浪费额度。
- 招呼文案固定为默认话术；弹窗有"编辑"可改，未动。
- 已招呼者再次点打招呼会进聊天面板而不是发第二次。

## 4. 判定标准（本次用户要求）
- 硬条件：最高学历 全日制 211/985/双一流 本科及以上（用户 BOSS 筛选未勾"只看第一学历"，即按最高学历算）+ 机械相关专业 + ≥3 年机械（结构）设计经验。
- 加分：机器人/非标/传动/工装夹具/FEA；减分/排除：职能方向不符（算法、CFD、售前、教学、纯仿真）、全职经验不足、跳槽过于频繁、薪资期望远超岗位区间（>25K 对 15-25K 岗，但机器人强相关者如李威 25-40K 仍可招呼让 HR 谈）。
- 全程"符合→直接招呼"由用户授权；出现硬性付费拦截（次数用尽）才停下问用户。

## 5. 提速建议（下次）
1. 用支持视觉的主模型（截图可直接入上下文，省掉"读图问答"往返）——见下方结论，先小实验验证坐标精度不退化。
2. 预先建立本机固定锚点表（本文第 1 节），跳过校准阶段。
3. 已招呼名单单独维护，避免重复核对。
4. 卡片信息足够时（城市/方向/薪资明显不符）不开详情，直接记录。
5. 减少详情滚动读屏：只读教育栏 + 最近 1-2 段经历 + 技能标签即判定。
